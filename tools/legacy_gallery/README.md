# Legacy Naruto gallery work in progress

This preserves the original source and metadata from the owner's request to see the old modded bosses in front/left/back/right views. The curated roster contains 37 named characters, 20 additional combat NPC types and all ten tailed beasts, with 268 planned views. Extra NPCs are not described as bosses. Private CustomNPC exports/skins are outside this roster.

The native gallery joined on loopback 25587 and a four-angle human lineup was visibly observed. Boss singleton rules, revival/duplication and an elevated-floor lighting stall prevented complete acceptance. The alternative client-only helper constructs registered entities and invokes their original renderers without adding ticking actors to the world. Its build passed and the client logged `GALLERY_MODELS_READY 268 failures=0`, but rendering exceptions followed. This helper is unfinished. No all-model visual success is claimed. The owner stopped computer control with Escape; do not relaunch over an inspection session.

`collaboration/legacy-boss-gallery/roster.json` is the curated registry/label/source-hash/position record. The flat `experimental-roster-list.json` is the list-shaped input expected by the first launcher. `release/evidence/legacy-boss-gallery-20261113.json` records bounded evidence and next steps. No mod JARs, artwork, worlds, private logs, launch recipes or authentication files are included.

`catalog.py <private-mods-directory> <output-json>` preserves the initial static extraction approach. It reads Java metadata and language strings without executing reference code. Its display-name/registry-ID join needs reconciliation: the Rogue Anbu entry is registered as `kabutoaddon:anbu` even though its language key is `rogue_anbu`. The curated roster and helper TSV correct that ID. Do not treat the raw extraction as authoritative.

`tools/legacy_gallery_preview/` contains the original helper source, four-angle TSV, and RFG build. Build from the repository root with the pinned wrapper, JDK25, the Azul JDK8 toolchain and optional reviewed stable-39 Minecraft development API, as for other modules. Select `-p tools/legacy_gallery_preview writeValeBuildMetadata`. The copied settings retain the historical Gradle project name `field-hud`; this experiment is not the production Field HUD component.

`experiments/` preserves the setup/population/client launch code. `VALE_GALLERY_BASE` replaces the private machine-specific parent directory. These scripts depend on the pre-existing reviewed 0.3.12 runtime layout, synthetic offline recipes and local Java/Forge inputs; they are not general installation tools. Historical defects are retained for recovery: the initial launcher excluded the actual Rogue Anbu ID, the population routine could acknowledge queued work before server execution, and the second helper still throws rendering exceptions. A submitted row or successful object construction is not a visual verification. The source was moved to portable public paths; syntax was checked, but the adapted launch scripts were not rerun.

Next: diagnose the nested rendering error, reconcile catalog IDs, then verify all four views for every roster row in a new isolated profile. Preserve the original worlds and the owner's current games.
