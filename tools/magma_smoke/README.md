# Disposable Magma bootstrap/restart

The default flat-world stage creates a **new** private candidate from verified server intake, preserving archived JAR identities. It excludes recovered worlds, archived credentials/configs, global NPC scripts and exploded loose classes. The explicit copied-world profile below adds separately verified world/dependency inputs. Only mods explicitly declaring `clientSideOnly` are omitted automatically; every omission is recorded.

```powershell
python -m tools.magma_smoke stage --recovery D:/verified-recovery --candidate D:/new-flat-candidate --dependencies D:/reviewed-dependencies.json
python -m tools.magma_smoke boot --candidate D:/new-flat-candidate --java-home C:/approved-windows-java8 --label boot-01 --timeout 300
python -m tools.magma_smoke boot --candidate D:/new-flat-candidate --java-home C:/approved-windows-java8 --label boot-02-restart --timeout 300
python -m unittest discover -s tests -p test_magma_smoke.py -v
```

The dependency plan is a reviewed JSON array of `{ "target": "libraries/...jar", "source_path": "<approved local file>", "sha1": "<published pin>" }`, or `url` instead of `source_path`. Only HTTPS endpoints on the explicit official repository allowlist are accepted; final redirect hosts and size/hash are checked. Dependencies cannot overwrite archived payloads. The Minecraft server target `minecraft_server.1.12.2.jar` is also permitted. Stage receipts record SHA-256 and independent disk readback. Raw JARs are not public release artifacts.

Boot requires a disposable marker, exact archived Magma SHA, fresh-profile flat-world name, loopback `127.0.0.1:25579`, offline local mode, RCON/query off and a Windows PE Java 8 executable. JVM memory is fixed at `-Xms512M -Xmx2G`. Java starts without a visible process window. Console logs and receipts remain private. The server receives `list`, `save-all`, `stop` after `Done`; boot completion, saved chunks, shutdown, exit status and any forced termination are distinguished. It never launches archived startup scripts or Linux Java. Each run label is new so earlier logs survive.

The explicit `enhance` action instead creates another new candidate on loopback port **25580**. It accepts `--recovery`, `--candidate`, `--dependencies`, `--source-root`, `--build-report` and `--native-report`. Passing source/native receipts must bind the exact nine `run_native_checks.PRODUCTION` server components and the requested Core 0.3.11 hash. It retains the archived `hvdungeonpictures` JAR under `retained-originals/`, installs tested Village Standards as its sole active registry owner and pins `canonicalEquipmentCatalog=false` for legacy equipment coexistence. The private source/native reports are copied with verified hashes. Before each enhanced boot, the added artifacts, retained original and compatibility setting are verified. `boot` uses the reviewed profile's port; other bind/port changes are rejected.

This tests bootstrap and clean restart only. It does not establish normal-client gameplay, every addon hook, crafting recipes, restored server settings, NPC scripts, copied production worlds, historical loose-class patches or hosted deployment compatibility. See `docs/magma-smoke-current.md` for observed results and remaining defects.

## Explicit copied-world profile

`world-stage` creates another new candidate from a stopped enhanced runtime plus an explicitly **FROZEN**, pinned world receipt. It verifies every source/copy/readback hash and keeps a pending marker that the flat-world boot guard refuses. It takes `--runtime`, `--world-source`, `--frozen-receipt`, `--receipt-sha256`, `--candidate` and optional `--memory 2G|4G`. It uses the runtime's private pinned 0.3.11 JARs/receipts, never the latest mutable build reports.

`world-review --candidate ... --recovery ...` parses every region's entity/tile NBT and the original global/world NPC libraries without execution. Nonempty inline/standalone scripts or parse failures block this supported no-executable-script profile. The private report contains source hashes and may contain script text; keep it outside Git.

`world-seal --candidate ... --recovery ... --script-review ... --runtime-level ... --memory 2G` verifies complete review coverage and zero missing saved registry names against an already booted exact enhanced runtime. It copies only the explicit legacy mod/NPC/Armourer's Workshop/proper CrazyCrates allowlist, rejects nonempty credential-like fields and preserves the newer world's NPC/player data. It excludes archived server/access/network configs and unresolved stray root plugin YAML. Successful sealing enables a distinct reviewed copied-world guard on **127.0.0.1:25581**; it does not bypass or weaken the flat-world guard.

Each copied-world boot checks the sealed input or preceding clean post-stop world snapshot. Every run records a complete private post-stop world hash snapshot. A failed previous boot blocks casual restart and remains preserved; no missing-mapping confirmation/discard command is sent. This profile allows a 4 GB cap when explicitly selected; the observed current two boots used 2 GB. Matching full-pack client acceptance remains separate.

## Frozen 0.3.12 and matching graphical profile

`world-stage-0312` accepts the same frozen-world/runtime arguments plus `--frozen-inputs` and `--script-review-donor`. The input root must contain the exact published 0.3.12 build/native receipts and nine checked artifact copies. It retains all nine copied 0.3.11 components outside active mods, installs the nine frozen 0.3.12 copies and pins port **25583**. The old 0.3.11 profiles keep their original Core/version/port guards. An unknown release is rejected; port25582 remains reserved for the existing hand preview.

Review reuse is restricted to byte-identical frozen file/region manifests and complete no-script findings. NPC source hashes are checked again at sealing. Legacy registry preflight uses the already booted 0.3.11 map only when all eight non-Core additions are byte-identical and the source world has no `valeorders` saved names. That narrower reference scope is recorded; missing mappings are never confirmed or discarded. Actual 0.3.12 boots establish the later saved-world result.

`python -m tools.magma_smoke.all_mods_client` assembles the preferred **58** graphical JARs without launching: original49 minus old pictures, nine client components and OptiFine. Six shared JARs must match the server; HUD/Controls/Client Lifecycle replace the three server-only bridges. The committed 0.3.12 receipt, live donor receipt, all external launcher pins and vanilla asset objects are checked. A fresh synthetic identity, four-GB cap, legacy catalogfalse and JER DIYfalse are explicit. Worlds, accounts, server scripts and old startup scripts are not copied.

`--inventory-tab-workaround` explicitly creates another new profile with the same58 JARs and a single verified `CustomNpcs.cfg` option changed to `InventoryGuiEnabled=false`. Original config bytes are preserved outside the client, and a separate variant receipt records before/after hashes and the untouched base assembly receipt. Unknown, missing or duplicate option forms are rejected. This bypasses the observed CustomNPCs off-thread quest-tab screen-open path; it removes those inventory tabs and does not repair the underlying dispatch. It never launches the profile or changes OptiFine/other JARs.

`python -m tools.magma_smoke.live_console --candidate ... --java-home ... --label <new-label>` starts a guarded hidden server and leaves it running after Done. Private state is `PRIVATE-LIVE-CONSOLE-SESSION.json`. Atomically create a unique JSON file in its recorded request directory, e.g. `{"commands":["list"]}` or `{"commands":["save-all","stop"]}`. Each response records sent/rejected status. Commands go only to the owned Minecraft stdin; no shell is invoked. Mapping confirmations and multiline injection are rejected. A clean stop records the final world snapshot and receipt. This controller never launches a client.
