FIRST INSTALLATION AND HOST SETTINGS
1. Copy this complete server tree to a new deployment/test folder.
2. Before editing its configuration, use an installed Java 8 executable from
   that copy's server root:
       java -jar server.jar --vale-upgrade-check-only
3. Require successful exit and the VALE_DEPLOYMENT installation message.
   This command verifies the initial pinned files and writes genuine
   installation state. It can preserve explicitly retired files in its
   rollback area. It does not start Minecraft or prove runtime acceptance.
4. Apply only the required host port/bind changes to this deployment copy.
   The reviewed defaults are server-port=25565 and an empty server-ip.
   Compare them with the real Bisect allocation. Keep the genuine installation
   state with the copy; never manufacture a marker or edit the original pack.
5. Record configuration changes and a new complete file inventory. A derived
   deployment ZIP needs its own filename, byte count and SHA-256.

BISECT IMPORT
Keep a recoverable backup and use a stopped, clean target instance.
Use Minecraft Tools > Modloader > Custom and the custom-JAR choice for
Minecraft 1.12.2. Upload the complete prepared deployment tree or its ZIP,
including the genuine installation state and reviewed host settings from the
steps above. Use SFTP and unarchive the ZIP directly into the server working
root. server.jar,
server.properties, mods, plugins, libraries and Naruto.test must be alongside
one another, without an extra outer server folder. Set Server Jar File to
server.jar and select the panel's managed Java 8 runtime. The retained
CustomJAVA directory contains Linux files; it is not a Windows Java install.
