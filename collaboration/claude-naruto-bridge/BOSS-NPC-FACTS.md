# NarutoMod boss/NPC bridge facts for Claude

This is a static read-only intake of the owner-supplied pinned49-JAR pack. All49 SHA256/byte identities matched the repository inventory;12 relevant JARs also passed ZIP CRC. No JAR/class was loaded or executed, no method-body attributes were exported, and no artwork/class/JAR bytes are included here. Public/protected signatures and constant-pool references are facts about this exact binary, not a claim of a supported stable SDK or native integration success.

## Boss/NPC identity

`boss-npc-registry-table.csv` lists67 curated entities (37 named characters,20 other combat NPCs,10 tailed beasts). Every ID has exact namespace and key literals in its registration-owner class.64 have one referenced living-class candidate. Naruto Itachi, Kabuto Edo Itachi and Naruto TenTails reference additional appearance/split living classes: resolve those against the actual EntityList registry in a disposable native run before rewarding. Names, display labels and numeric registration IDs are not durable boss identity. Correct Rogue Anbu is `kabutoaddon:anbu`, not a language-key-derived `rogue_anbu`. This is not an exhaustive private CustomNPC roster.

## Items and rewards

`BOSS-NPC-FACTS.json` → `item_symbol_links` joins referenced public item fields to exact item-model/registry literals. It does **not** assert equipment is a drop. For example, Itachi references MangekyoSharingan helmet, Akatsuki robe/hat and kunai symbols. Those references may be equipped gear, jutsu dependencies or initialization, not rewards. Multi-piece field families remain explicit candidate mappings. Never infer a rare eye drop from a held/rendered item or localization label.

Core's current `RewardLedger.issue` accepts only `Gear.ITEMS`; it does not issue arbitrary `narutomod:*` items. `issueOwned` separately permits reviewed `hvbijuu` rewards. A boss bridge therefore needs a bounded reviewed external-reward API or must award supported Core items. Keep a server-issued encounter/run token, exact entityUUID+registry+dimension, eligibility source and per-player receipt. `RewardLedger.valid` checks serial+owner+item; an unowned bare `/give` is not valid Core reward gear. Naruto eye ownership additionally exposes `ItemSharingan$Base.setOwner(ItemStack,EntityLivingBase)`; do not assume copying an NPC's eye stack transfers ownership correctly.

Recommended ORIGINAL contribution contract, not yet implementation: observe final event references and accepted native health+absorption delta; resolve projectile immediate/true source and owned summons to a real player; reject canceled/zero/NaN hits, cross-world targets and spectator/fake/unowned actors; cap contribution to accepted loss; keep one terminal encounter receipt; defer terminal-death settlement and reject canceled/revived/removed/transformed impostors; issue durable queued rewards once. Use per-hit identity to avoid another hit/heal masking the first, and deduplicate Forge/CustomNPC notifications. Offline participant identity/outbox delivery must survive reconnect/restart without reusing a changed run. Sealing/phase transitions require their own explicit completion receipt.

Required disposable native checks: finalHurt/Damage/Death cancellation; absorption-only acceptedhit; later heal/source overwrite; indirect projectile and summon ownership; fakeplayer/teammate/spectator rejection; canceled death then revival; duplicate death across buses; Edo/appearance clone/split beast; world/UUID replacement; native original XP/drop coexistence; partial inventory/full inventory delivery; offline/reconnect/restart pending receipt; optional dependency absent/version mismatch. No live015 session, world, UI, shader or mod was changed by this intake.
