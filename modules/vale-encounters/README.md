# Original Encounters036 candidate

Isolated Forge1.12.2 implementation. No Core035, actual-stage, original ZIP or stable parity095 files were edited. This standalone candidate needs the original Core ArsenalAccess API and the new Core036 EncounterRewards API for boss settlement. Root owns combined integration and publication.

`CANDIDATE-MANIFEST.json` pins the production jar. `source-profile-catalog.json` maps136 legacy technical IDs to wholly original named profiles:70mobs,29bosses,37companions. Three entity classes are registered under valeencounters:mob, valeencounters:boss and valeencounters:companion. Profile keys, health, finite support charges, companion ownership/lifetime, and actual boss contribution data persist. No original implementation, textures, dialogue or character designs were copied. Vanilla biped/Steve references are temporary visual stand-ins; visual design remains deferred.

Hostiles have real bounded telegraphed melee, locked ranged, marked area and damage-gated control attacks, plus finite healing, guarding and collision-checked short movement. Bosses change approach below65% and30% health and expose a vanilla boss bar. Only eligible living noncreative/nonspectator players can be hostile targets. There are no block edits, explosions, fire spread, native loot or XP drops. Damage flows through normal vanilla/Forge protection; control effects require observed accepted damage. Companions provide four implemented support engines (vanguard, warden, mender, scout), follow their owner, respect the original core's damage authority, reject friendly NPC targets, and expire on owner loss/death/dimension change or their bounded lifetime. One living companion per owner is enforced by the server summon hook.

The public read-only commands are `/valeencounter list [page]` and `/valeencounter info <profile>`. `/valeencounter spawn <profile>` separately checks OP level4 before mutation. No natural spawns or automatic population flood is enabled. Hostile command spawns are capped at128 loaded actors. Public `Encounters.show(EntityPlayerMP)` supports a normal player's dossier/book without arbitrary command execution. `showList` and `info` are read-only; `create` and `summon` are trusted server APIs. Core callers of summon must enforce their own learned ability, cost and cooldown rules.

Bosses call Core036's boolean `EncounterRewards.award` with their profile key, tier1..5, actual damage contributions and last-hit times. Tiers are also stored under entity data `valeEncounterTier`. `EncounterRewarded` is set only after a successful return; failed settlement retains the dead entity for idempotent retries. Reward receipts and eligible offline payout authority remain entirely in the core. The included compile-only API declaration is not packaged in runtime jars. Native baseline checks used Core035, so actual Core036 reward settlement and mission XP require Root's combined native acceptance.

The production jar excludes NativeChecks and all API shim classes. A separate private probe jar is retained under build/private-native-proof. In a disposable isolated headless Magma/Forge world,501 native checks passed: all136construct/save/load paths;29boss tier bounds; representative real AI windup/damage, ranged evasion, area/control, cancellation without secondary effects, friendly-NPC protection, guard/heal/safe mobility, phases/contribution persistence; all4companion engines and expiry; public read-only permission and independently denied unauthorized spawn. Production actor bytecode and profile payload match that native-tested probe. The last production-only difference is spacing in roster explanatory text. No GPU/client rendering test was performed.

`config/valeresidents/dialogue.json` contains11new original dialogue pages for the existing academy/contracts/quartermaster roles. It covers help, progression, provisions, crates, racks and recovery. The real Residents0.2 native parser accepted this exact config. It is not installed into the actual server; live service actions and installation-specific crate/rack behavior remain integration checks.

This is an original functional roster built from shared engines, not a claim that every unique legacy mechanic is reproduced. Every catalog row explicitly retains unverified legacy obligations. All37companions have real bounded engine behavior, but their normal-player acquisition and unique old summon mechanics are not established by profile labels. There are no spawn eggs, natural distribution rules, world migration assignments, or complete legacy-parity percentage in this candidate.

Build with the existing Gradle9.5/RFG2.0.3 setup and prepared MC API input. `-PencounterProbe` adds private QA classes to a probe build; never ship that variant. Rebuild without the property for the clean production artifact. The runtime profile JSON and original dialogue have deterministic authoring scripts. Root should integrate the pinned clean jar, the intended dialogue config, Core036 rewards/missions, and an audited companion acquisition path before claiming an end-to-end release.
