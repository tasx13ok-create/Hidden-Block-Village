VALE RESIDENTS0.2.0 — ORIGINAL ROLE/DIALOGUE AUTHORING

Minecraft Java1.12.2 Forge; requires the owned Vale Orders0.3.x on client/server.
Install this JAR on both sides in place of Residents0.1; never install both.
Entity identifier valeresidents:resident and existing owned role/UUID schema are
retained. The module has no CustomNPCs, Varied Commodities, Armourer's Workshop
or carpentry-adapter dependency. Its renderer references Minecraft's villager
model and librarian/farmer/smith skins; no game/third-party skin assets are bundled.

Three useful server roles:
 - Academy: original greeting/advice pages, then the owned technique academy.
 - Contracts: review Core contracts, accept configured contract IDs, and turn in
   completed work through Core's actual cost/progression/reward receipt logic.
 - Quartermaster: order-equipment/tools/spirit menu routes through Core authority.
   Available stock depends on the installed owned Core/armor provider and gates.
No custom item grant, arbitrary server command or script action is allowed here.

RIGHT-CLICK A RESIDENT, THEN CLICK A CHAT CHOICE.
Choices bind to player UUID, actor UUID, world, page and the current definition
generation. They expire after600 server ticks, require a living nearby actor and
non-spectator living player, and are consumed before dispatch. Retalking replaces
the previous conversation. Logout, world unload and valid reload invalidate it.
At most256 conversations are retained. /residentchoose is the native level0
choice transport; its opaque token is generated by the server, not an admin API.

AUTHORING (permission level2):
 /valeresidents status
 /valeresidents provision
 /valeresidents reload
 /valeresidents title academy Riverbank Guide
 /valeresidents move academy <x> <y> <z>
Roles: academy, contracts, quartermaster. Moves require a loaded existing supported
actor and safe, empty, already loaded destination with solid ground. No chunks
are forced, UUIDs replaced or missing residents silently respawned. Names and
placement use native entity persistence; saved home updates preserve extensions.

First server startup creates config/valeresidents/dialogue.json if it is absent.
Edit that original JSON and run reload. Schema1 requires all3 roles; each has a
start page and1..16 pages,1..4 lines/page,1..6 choices/page. Lines <=200 characters,
labels <=64, identifiers <=48, file <=64KiB. PAGE targets must exist. Explicit
actions are PAGE,ACADEMY,CONTRACTS,QUARTERMASTER,TOOLS,SPIRIT,ACCEPT_CONTRACT,
CLAIM_CONTRACT. Only PAGE and ACCEPT_CONTRACT have a target. The latter is an owned
Core contract key; Core rejects unavailable/unknown/locked contracts. See example.
Unknown schema/fields/actions, invalid graph, malformed/oversized file are rejected
without overwriting the file or previous valid runtime definitions. A valid reload
publishes the entire book, then clears earlier conversation tokens.

Provisioning/protection remain bounded:3 roles maximum, safe loaded overworld-spawn
ground, at most6 startup attempts and no natural-spawn entry, egg or chunk ticket.
Residents stay in place and reject ordinary damage/push/leash. Missing/conflicted
UUID slots stay reserved; unsupported future entity/world data remains preserved.
config/valeresidents.cfg controls autoProvisionOverworld and maxResidents0..3.

BUILD
Gradle9.5 / RetroFuturaGradle2.0.3 / Java8 toolchain / MCP stable39.
 gradle -PvaleApiJar=<owned-core-0.3.3-dev.jar> build reobfJar

executes54 native-NBT component checks and21 bounded dialogue-definition checks.
Native server/actual restart evidence and exact runtime pins are supplied in the
verification report. Headless native checks use a simulated non-op player; this
release does not claim a new graphical/network-client test of0.2 dialogue.

SCOPE
This completes the required3 owned role gateways and small original authoring
flow. It is not a CustomNPCs API implementation, arbitrary NPC job/AI/model/skin
editor, script runtime, general quest/faction/bank engine,4x4 carpentry workstation,
Varied Commodities furniture/item library or AW skin system. Owned Core supplies
missions/merit/rewards. Hosted legacy world/NPC/quest/player/key data is unavailable
and has not been converted or migrated. Read COVERAGE.txt for exact gaps.
