# Server arena runtime

`modules/naruto-arenas` is an original, server-only Forge 1.12.2 module. It registers no new blocks, items, entity types or client renderer. The five geometric templates remain vanilla Alpha schematics. The module resolves the installed original boss registry entries at runtime; it preserves their native AI, attacks, costs and native death/revival rules. Environmental encounters are labeled original adaptations rather than native jutsu implementations.

## Identity and admission

`config/naruto-arenas.json` is generated from one explicit, SHA-256-bound build manifest. Each arena has its own template hash, world plot, authored landing points, gold mechanic nodes, three service positions, route samples, lamps, storage tiles and (for Mist) contained water-prison volume. A configuration boolean cannot authorize its own terminal adapter. Candidate earned admission uses the five built-in exact registry/class-resource/provider-JAR sealing policies, backed by recorded per-provider native flows. The final candidate must re-observe ordinary admission and full sealing/replay on its exact bytes before acceptance; unknown providers remain closed. Native-death acceptance is a separate policy table and is not implied by an accepted seal ending.

Normal participation requires an actual registered, living Survival player. Spectators and Forge fake players are rejected. Creative preview is distinct and cannot issue normal arena or starter entitlements. Each actual party member completes the short, two-node physical introduction; the saved intro can award native battle experience and one canonical native chakra seed, while preserving native nature and existing profile data. There is no replacement Resolve pool. Existing advanced characters can use their own equipment and native resources.

The optional once-only starter is four genuine matching Core Ward pieces and a basic matching saber issued through the public Core reward ledger. The player chooses an order outside an active run; the selection persists globally for that UUID. Stable per-part ledger receipts retain full-inventory deliveries across logout/restart and prevent replay or replacement of previously delivered gear. This does not assign the global Core starter order or a native nature.

## Player commands

- `/narutoarena list` lists the five configured identities.
- `/narutoarena intro <id>` begins the arena's short physical practice.
- `/narutoarena kit list` and `/narutoarena kit <order>` inspect/request the optional once-only starter after practice.
- `/narutoarena enter <id>` starts a normal run; `/narutoarena join <id>` joins its party, up to four actual players.
- `/narutoarena preview <id>` starts a clearly separate preview run.
- `/narutoarena status` displays the saved state.
- `/narutoarena claim 0`, `claim 1` or `claim core` selects one entitlement mode at the reward scene. Core rewards are genuine owned matching armor and an Arsenal moveset weapon.
- `/narutoarena exit` uses the authored safe return landing and retains pending entitlements.
- `/narutoarena retry` reopens a saved recovery checkpoint after bounded chunk prewarming.
- `/narutoarena reset <id>` remains an operator recovery tool. Ordinary replay uses automatic conditional empty reset after the last online member exits.

## Encounters and terminal outcomes

Each arena has three different environmental beats with a 30-tick warning, a bounded attack volume, native damage/guard handling and a recovery window. Two distinct authored gold nodes interrupt each physical seal sequence. Completing the second node requires 40 separately observed actual boss updates with a legitimate participant within 32 blocks during that sequence. The persisted `seal_pressure_ticks` counter is separate from reward contribution; proximity earns no entitlement. Reboot resets the in-memory tick baseline rather than inventing a time delta. Final event cancellation, the exact login/body/connection, dimension, node, run and sequence epoch are checked after the original Forge interaction returns. Merely clicking, standing nearby or damaging a different entity gives no arena credit.

Forest uses root lanes, a connected original wooden dragon and Sage bloom sectors. Cloud uses lariat lanes, alternating grounded crown sectors and a guillotine center commitment. Sand uses guard sectors, burial lanes and diagonal desert convergence. Mist uses shark lanes, the authored off-center contained water prison with real stair exits, and chakra-pressure lanes without an additional chakra debit. Fire uses fan sectors, a connected original guardian presentation and two bounded meteor volumes. These additions do not replace native boss attacks.

An accepted native lethal outcome and an original arena seal are different outcomes. A native finisher is credited only after retained final uncancelled death evidence, exact owned identity, absence observation and replacement checks. A seal requires all three genuinely earned physical sequences, conditionally restores owned cells, removes only the exact run-owned boss, then observes 200 loaded-world ticks for unexpected living actors or replacements. It does not claim native death, native death XP or universal Edo immortality. Ay allies are authenticated through the actual public leader API, exact inspected class/JAR identities and post-baseline UUID records; unrelated or pre-existing actors are preserved.

## Persistence and reset

WorldSavedData uses a bounded 4 MiB UTF-8 byte-array envelope, with legacy NBT-string reading. Unknown schemas/envelopes are preserved read-only. There are at most five active arena records, 4,096 owned cells per run and bounded admission/reward archives. Journal positions use an identity-scoped index rather than a quadratic scan.

Terrain changes write and flush their before/after journal before mutation. Restoration checks current native state against the recorded owned after-state (or the finite owned water family), verifies the actual restored state and retains every conflict. There is no blind live schematic paste. Reset refuses an occupied combat cell, a player intersecting an owned cell, mismatched actor identity, ambiguous native ally or conflicting terrain. Automatic reset retries at a bounded interval and archives every eligible offline participant before clearing membership.

Native item rewards save the item and its replay receipt in the same actual player-data save. Full inventory leaves a durable pending entitlement; it does not overwrite slots or drop a reward. The per-owner archive survives exit and subsequent arena runs. Genuine Core rewards use Core's own public serial/ownership/offline outbox policy rather than forged tags.

## Verification boundaries

`tools.arenas.native.run_checks(candidate, cases='all')` creates a new isolated headless Magma copy from the exact world-stage marker and manifest hash. It validates the current stopped server's pinned 53-mod roster, adds this module plus a separate private QA JAR, and keeps the owner's worlds and running server untouched. Optional server Damage Indicators remains omitted as recorded by the approved server assembly. Inspected compatible baseline libraries/configs/plugins are recorded separately; their equality with the current stopped server's configuration is not assumed.

The `registry`, `controller`, `restart` and `nether` selections report narrower scopes explicitly. Restart mode uses seven real save/stop/new-process boots of the same private copy, covering PHASE1/2/3, seal observation, full-inventory pending reward, delivery and reset. Nether mode requires its independently prepared cold DIM-1 marker. Ports are explicit loopback-only fixture ports. Load measurements from concurrent functional fixtures do not constitute the final standalone benchmark.

Fresh native fixtures require `spawn-monsters=true` for the actual Gaara EntityMob join, while the staged world uses `doMobSpawning=false` to prevent ambient spawning. Their `keepInventory=true` and `keepNinjaXp=true` death policy is checked through the actual public native API. These candidate settings are explicit rather than edits to a running owner server.

The staged Anvil starts with unpopulated light arrays. Native checks request real block/neighbor propagation before reading light; they do not invent light values. A pristine cold stage is not claimed native-lit before that initialization. A delivery based on the Anvil world must retain actual native initialized arrays or run the documented native prewarm before use.

The private harness uses official server logins and actual native player/entity ticks, public NetworkManager packet processing and real keepalive/teleport acknowledgements. It guides server positions and physics; it is not a rendered client, human traversal or network gameplay acceptance. Minecraft remains closed. Native route collision/support, light, palette, storage tiles, services, accepted/cancelled combat, party ownership, reward receipts and process restart results must be read from the exact matching private receipts. A component compile, static registry CSV, zero process exit or a known-failing earlier cohort cannot substitute for a passing gate.

Nonlethal damage/healing/protection contribution still requires an authoritative accepted-contact observer surface. The module does not credit attack intent or a later unrelated health change. Physical objectives and confirmed native finishers are the implemented contribution paths. Direct native terrain writes outside the journal remain subject to actual post-native world comparison and the world package's cold rollback; no global native-provider manager is modified to hide a failure.
